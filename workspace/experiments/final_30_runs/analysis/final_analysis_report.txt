RESEARCH INTERPRETATION
----------------------------------------------------------------------
The experiment evaluates locally deployed LLMs for automated Python security vulnerability repair using the same repository, vulnerability instances, context, and automated validation pipeline.
Final verification requires both successful regression testing and removal of the targeted Bandit vulnerability.
Therefore, syntactically valid patches or patches that pass regression tests are not automatically considered secure.
Generation/runtime failures are separated from patch-quality failures because a model may fail to produce a patch before its security-repair capability can be evaluated.

IMPORTANT LIMITATION
----------------------------------------------------------------------
This experiment contains 30 runs across 10 vulnerability instances and 3 locally deployed LLMs. The results indicate performance on this benchmark and should not be generalized to all Python vulnerabilities or repositories.

FINAL RESEARCH CONCLUSION
----------------------------------------------------------------------
Across the 30-run evaluation, the models demonstrated different levels of secure patch generation and runtime reliability. Llama 3.1 8B achieved the highest overall verified patch rate at 70.00%. The comparison shows that model selection affects both the quality and reliability of automated security patch generation.
The results also demonstrate the importance of automated security re-scanning. A generated patch may be syntactically valid and pass regression tests while still failing to remove the targeted security vulnerability.
Consequently, SecurePatch uses a verification pipeline combining patch application, regression testing, and Bandit re-scanning before accepting a patch as VERIFIED.
